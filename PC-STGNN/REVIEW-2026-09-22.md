## 1. Spec-level errors (would have invalidated Stage B)

### 1.1 The corpus load is one global scalar, not per-bus — FIXED IN FILES, DECISION

`fault_localization/simulation/runner.py:116` draws `load_multiplier = rng.uniform(0.5, 1.3)`
once per event; `monitors.py:196` applies it uniformly to every load
(`_scale_loads_from_base(base_loads, load_multiplier * step_mod)`), with a deterministic
0.3 % sinusoidal modulation over the 40 pre-fault steps and the load frozen at the step-39 value
during the fault. The stored metadata field is a scalar (`meta["load_multiplier"]`).

Consequences for the plan as written:
- 01_SPEC §2 "per-bus multiplier, independent per bus" is false; the "why an ensemble, not a
  global load grid" paragraph argues against the corpus's own generative process.
- S1.5 (dispersion of 50 runs vs σ_load) is not an "exact" test of a per-bus load model — the
  50 runs of a scenario lie on a **1-D curve** parametrised by L. Diagonal σ_load is the wrong
  model for that: S1.6 would find channel correlations ≈ 1.0.
- S0.2's "per-bus vector" check is answered now: coverage is 100 %, and the vector is a scalar.

Applied fix (01_SPEC §2–4, 03 S1.2/S1.5/S1.6): L becomes an explicit **profiled axis** on a
17-point grid (0.5–1.3, step 0.05), (τ, R, L) are minimised jointly, the denominator becomes a
fixed floor σ_ε² + σ₀², and S1.5 becomes the sharper test "argmin_L recovers the stored
`load_multiplier` within one grid step". Table cost 25×11×15×17 ≈ 70 k solves (+17 for no-fault).
The ensemble version is kept in the spec as the rejected alternative, with the reason.
**DECISION:** confirm this is the operator you want before Stage B starts.

### 1.2 No residual for the no-fault class — FIXED IN FILES

r̃ was defined over 25 locations only; z ∈ ℝ²⁶ and 50 % of windows are class 0. Without
μ₀[L] (no-fault signature) PSM cannot output "no fault", B1/B2 F1 is capped near 0.5, and the
β-fusion never touches the no-fault logit. Added μ₀[L] (17 solves) and r̃₀(A) = min_L ….

### 1.3 Observation vector needs metadata the model does not have — FIXED IN FILES

"s_ip = mean of the post-inception timesteps" requires the window's offset inside the event,
which is not in the `[25, 20, 6]` tensor and violates the inputs-only rule (01_SPEC §5). Replaced
by **s_ip = last timestep of the window**: the fault period is quasi-static with loads frozen
(runner.py fault loop never rescales loads), so every post-inception sample is the same level and
the last sample *is* it whenever the window has ≥ 1 post-inception sample. For window 20
(0 samples) it returns the pre-fault level and the residual correctly prefers class 0 — the
"physics disabled" policy falls out without any offset. S0.3 now includes a one-line check that
post-fault samples within a window are constant.

### 1.4 Window census is analytic — FIXED IN FILES

`labels.py:79`: windows 0–19 no-fault, 20–39 fault (window w covers steps [w, w+20), inception
at 40). Fault window w has w−20 post-inception samples: **1 of 20 (5 %) has zero, 5 of 20 (25 %)
have 1–5.** S0.3 is a confirmation script, not a measurement; the "> 25 % → add a column"
branch does not trigger.

### 1.5 Normalisation — FIXED IN FILES

`data/dataset.py:61` z-scores voltage channels with training-split stats before the model sees
them. The residual must run in p.u. — compute r̃ offline from the raw `.npz` (the caching path
already recommended in S3.4) or de-normalise inside the layer. Not stated anywhere in the plan.

### 1.6 Wrong Paper-1 numbers — FIXED IN FILES

01_SPEC "Known weak points": SDR-STGNN AUDC is **0.892** vs dropout-aware **0.913**
(`paper/figures/sdr_robustness_summary.csv`), not 0.895/0.916 (those are pre-bugfix);
dropout-aware k=10 F1 is **0.674**, not 0.676. The 10 Ω figure 0.676 is correct
(`overleaf.tex:437`). The paper has no "Table 6" — cross-references were changed to
`tab:baseline` / `tab:degradation` / `tab:aware`.

### 1.7 Smaller spec points — FIXED IN FILES
- Uninstrumented phases carry voltage 0.0 and mask 0 (`monitors.py`); only 14 of 25 nodes are
  three-phase, so |A| < 75 even at k = 0. "All 75 channels" → "all instrumented channels".
- σ_load ≈ 0 on load-insensitive channels would blow the residual up — now a fixed floor.
- S0.4 tolerance 1e-3 p.u. must absorb the 0.3 % pre-fault modulation (frozen at step 39 →
  factor ≈ 0.99953 of the drawn multiplier). The snapshot solve must use L × that factor.

## 4. Things the plan should expect (not errors)

- On a noise-free, deterministic corpus whose only within-scenario randomness is a scalar L,
  a table from the same simulator with L profiled is close to an exact generative model. The
  Gate-2 branch "PSM ≈ or > STGNN at k = 0" is the **base case**, not a corner case. The paper
  then lives on noise (σ₀), dropout, silent failures, and the S6.2 mismatch study — plan for that
  framing from the start.
- The matched-filter 0.162 vs whatever B2 gets is the single most persuasive number for the
  operator design (profiling + load + driving-point term). Keep both rows.
- Relative AUDC is a known normalisation artifact in Paper 1 (`build_absolute_audc.py`); report
  absolute AUDC alongside it.
- S4.3 selects λ on validation F1 averaged over k while checkpoints are selected at k = 0 —
  legitimate, but state both rules.
- "Stuck at pre-fault value" needs a definition that is input-only: freeze the sensor at its
  first-timestep value in the window. Added to 05.
