## Part 3 — Speed measurement (non-physics arms)

**Method.** `scripts/measure_s4_4_timing.py` (new script, this round). Builds each arm via the
same `PCSTGNN` class and `pc_train_epoch`/`pc_loss` path `experiments/runner.py` itself uses
(not a simplified stand-in), with `use_fusion=False`, `lambda1=lambda2=aux_net_loss_weight=0`
(γ=0, consistent with Part 2's design rule), noise augmentation on (`σ ∈ {0, 5e-4, 2e-3, 1e-2}`),
dropout-aware training on (`k ∈ {0,1,2,5}`), `gnn_layers=4`, seed 42, same
`CUBLAS_WORKSPACE_CONFIG` determinism setting as a real run. For each arm: 200 training batches
(timed individually, CUDA-synchronized) then 200 validation batches (`model.eval()`, no grad).
No checkpoints saved; the only file written under `results/` is
`results/s4_4_timing/timing.json`. Run one arm at a time, sequentially, nothing else running on
the GPU (`nvidia-smi` confirmed idle beforehand).

**R7 caveat, unchanged from the first draft:** no "wider" width is specified anywhere, so this
measurement uses the baseline `gnn_hidden_dim=64` as a flagged placeholder. The script prints a
warning and sets `width_is_placeholder: true` in the output for this reason. **The number below
for R7 is very likely an underestimate of its true per-epoch cost.**

**Results** (`results/s4_4_timing/timing.json`, train/val batches-per-epoch from the real split
sizes: 36,094 train / 7,750 val at batch size 32):

| Arm | Mean train batch (ms) | Mean val batch (ms) | Epoch, training only (min) | Epoch, validation only (min) | **Epoch with validation (min)** |
|---|---|---|---|---|---|
| R0ⁿ | 20.37 | 6.30 | 12.25 | 0.81 | **13.07** |
| R1 | 20.78 | 6.32 | 12.50 | 0.82 | **13.32** |
| R2 | 20.45 | 6.34 | 12.30 | 0.82 | **13.12** |
| R7 (placeholder width) | 20.60 | 6.36 | 12.39 | 0.82 | **13.21** |

All four land close together (≈13.1–13.3 min/epoch) — expected, since `use_type_head`/
`use_decoder` each add one small `nn.Linear` on top of the same GRU(128)→4×RGSAGE-Max(64)
backbone, and none of them touch the physics table. **This is ≈4× faster than the 52 min/epoch
physics rate** — confirms the first draft's flag that applying the physics rate to these four
arms was a large overestimate, now replaced with a measurement rather than a guess.

## Revision 2026-10-09 (round 3) — epoch decision, measured scoring cost, Gate 4 started

**Epoch count decided: 20.** Mean signed Δ(F1@k=0, epoch15−epoch10) over the 5 S4.3ᵉ arms =
−0.0038 < 0.005 ⟹ 20 epochs per the fixed rule. Caveat: the mean of absolute differences is
0.0061, which would flip the rule to 30 under that reading — flagged, not resolved; the signed
rule as literally specified was applied.

**Scoring cost measured (not the old ≈6.3h placeholder), 2% of the validation split (4,960
windows) across the full k×σ grid, scaled ×50** (`results/s4_4_timing/timing.json`):
physics configuration (S4.3ᵉ selected checkpoint, λ₁=0, λ₂=0.1) → **5.93 h** full-split estimate;
non-physics configuration (random weights, `use_fusion=False`) → **0.63 h**. Physics costs
≈9.5× the non-physics rate — the ρ computation, not the backbone, dominates scoring cost.

**R5/R0ⁿ parameter counts measured:** R0ⁿ 95,258; R5 95,259; difference = 1 (the `beta` scalar).

**R7's "wider" width — confirmed genuinely undefined** anywhere in the docs or code (re-verified
this round). B2ᵃ's settings remain explicitly un-chosen, per instruction — see the B2ᵃ
implementation-plan note added this round in the chat report (not written into this file, since
the author did not ask for it to be).
