# S1.5 R-grid corrective fix — locked 2026-09-25

## The failure

`results/pcstgnn/audit/s1_4_7/s1_4_7_summary.pre_rgrid_fix.json` (28,875 training events,
original 15-point log-spaced `R_GRID`, 0.05–30 Ω): **S1.5 FAILED.** τ* correct 90.9%
(passes), R* within one grid step 99.7% (passes easily), but **L* within one grid step only
38.4%** against the >90% criterion.

Root cause, verified by isolation (not a bug): the corpus's training resistances
{0.1, 1, 10} Ω were deliberately kept off the 15-point log grid (see the original `R_GRID`
comment in `fault_localization/physics/grids.py`, preserved in git history at commit
`a116e2b`), on the theory that this is what keeps S1.7's "how far does argmin_R land from
R_true" check non-vacuous. Profiling L at the corpus's *exact* R (not grid-snapped) recovers
L* to within 0.006 of ground truth with a clean unimodal landscape. Profiling jointly over the
coarse, off-grid R axis lets a nearby-but-wrong R combine with a compensating L shift to fit
better than the (off-grid) true R + true L — corrupting L recovery even though R* itself always
lands sensibly.

## Two remedies compared (`scripts/diagnose_rgrid_candidates.py`)

Built two candidate tables (`results/pcstgnn/operator/rgrid_{hybrid,dense25}/`, never the
canonical `operator/`) and ran the generalized S1.5 check on the full training split against
each, alongside the original:

| R grid | n | L* w/in 1 step (overall) | R=0.1 | R=1 | R=10 | S1.5 pass |
|---|---|---|---|---|---|---|
| original (15pt log, corpus R off-grid) | 15 | 38.4% | 36.2% | 14.4% | 64.5% | ❌ |
| **dense25** (S1.7's own branch-on-failure remedy: 25 log-spaced pts, corpus R still off-grid) | 25 | 58.6% | 52.4% | 32.2% | 91.0% | ❌ |
| **hybrid** (`sorted(unique(15pt log grid, {0.1,1,10}))`) — **ADOPTED** | 18 | **97.3%** | 99.2% | 98.8% | 93.8% | ✅ |

The spec's own prescribed S1.7 remedy (densify) does not fix S1.5 — it only shrinks ordinary
discretization error, which was never the diagnosed mechanism. Putting the corpus's own R
values exactly on-grid does, decisively, and at every R stratum individually.

Full numbers: `results/pcstgnn/audit/s1_5_rgrid_diagnostic/rgrid_diagnostic.json`.

## What changed

- `fault_localization/physics/grids.R_GRID`: 15-pt log grid → 18-pt hybrid grid (union with
  {0.1, 1, 10}). `NUM_R` follows automatically (15 → 18); every downstream shape
  (`table_shape`, `num_hypotheses`, `unravel_hypothesis`) tracks it.
- Canonical `operator/` rebuilt against the new grid (`n_solves=84167`, 0 non-converged, 0 NaN,
  75s wall). Pre-fix table archived whole at
  `results/pcstgnn/operator/operator_15pt_pre_S1.5fix/`.
- `scripts/check_operator_calibration.py` re-run (`--checks bias load floor rgrid`) against the
  new table:
  - **S1.4** (construction check): median\|e\| dropped from 2.78e-2 to **1.31e-3** — expected,
    since most events' stored ground truth is now an exact (not nearest-neighbour) grid point.
  - **S1.5: PASS.** τ*=90.9%, L* within 1 step=**97.3%**, R* within 1 step=99.7%.
  - **S1.6 (residual floor) broke as a side effect and was re-calibrated.** The old
    `sigma_eps=5.145e-3` (chosen by S1.2 against the *old* table's discretization error) gave
    median r̄=0.0199 on the new table — far under the [0.3,3] pass band, because the new
    table's true-hypothesis error dropped along with the R-L compensation. Rescaled via
    S1.6's own branch instruction ("rescale by one global constant, chosen on the training
    split"): `sigma_eps = 5.145e-3 · sqrt(0.0199/1.0) = 7.2555e-4`. Re-run: median r̄ = **1.0000,
    PASS.**
  - **S1.7**: `frac_non_monotone_in_R` measured on the new 18-point grid is 0.573 (was 0.537 on
    15 points) — expected, denser R sampling catches more of the same physical non-monotonicity,
    not a new problem. Fixed an inconsistency while here: `check_rgrid`'s `effective_r_levels`
    call hardcoded `sigma_eps=5.145e-3` independent of the `--sigma-eps` CLI arg used everywhere
    else in the script; it now takes `sigma_eps` as a parameter, so it tracks the S1.6 rescale
    instead of silently going stale.
- Test fixtures with a bare literal `15` for the R axis (`tests/test_physics_residual.py`,
  `tests/test_pc_stgnn.py`) now read `grids.NUM_R`; `tests/test_signature_solver.py`'s
  `test_grids_are_the_specified_axes` no longer asserts uniform log-spacing (the hybrid grid
  isn't uniform) and instead asserts the three corpus values are present and the axis is
  strictly increasing. Full suite: 220 passed.

## Cost of the fix — documented, not hidden

S1.7's "argmin_R lands near R_true" check is now much less informative at exactly the three
values that matter: `r_star_exact_frac` rises from 64.8% to 95.2%, **partly by construction**
(R_true can now literally equal a grid point), not from improved operator fidelity. It is not
fully vacuous (95.2%, not 100% — some non-monotone cells still miss it), but any future S1.7
R-interpolation claim in the paper should be made against off-corpus R values, not {0.1,1,10}.

## S1.2 ρ-margin re-check (2026-09-25, `results/pcstgnn/operator/lgrid_post_rgrid_fix/`)

Re-ran `check_operator_fidelity.py --checks lgrid` against the corrected canonical table
(fresh `--out-dir`, not the stale `results/pcstgnn/operator/lgrid/` which holds the *original*
15-point-grid tables — reusing that path would have silently mixed regimes, since the script
skips rebuilding a step whose `mu.npy` already exists). Along the way, fixed a real memory bug
this exposed: `margin_distribution`'s `[B=3000, chunk_f, H, 75]` intermediate scales with
`H = 11·NUM_R·n_l`, and NUM_R's 15→18 growth pushed peak memory for the larger L-step tables to
~12–24GB on this 15GB box — OOM-killed 3 times reproducibly at the same point (step 0.05's
larger H) before being fixed by batching over events (`chunk_b=200`, a pure memory change,
identical rho/margin/PSM values per event).

**Interpolation error (L-axis alone) is essentially unchanged** — p99 5.768e-3→**5.756e-3**
(step 0.1), 5.145e-3→**5.141e-3** (0.05), 3.551e-3→**3.549e-3** (0.025) — confirming the
assumption below: the R-grid fix doesn't touch L-axis interpolation smoothness, so S1.2's
`l_step=0.05` choice needed no revisiting on that axis.

**The qualitative pattern S1.2 selected on is preserved on the corrected table:**
- Step-invariance at fixed physically-relevant σ (σ=5e-3): median margin 71.8/70.0/70.3 nats for
  steps 0.1/0.05/0.025 (within ~2.5% of each other) — was 44.75/44.72/44.40 (within ~1%) on the
  original table. Still essentially step-invariant, just uniformly shifted up.
- At each step's own discretisation σ, step 0.05 still sits in the middle: saturation
  (frac>10nat) 64.8% (0.1) / **65.4%** (0.05) / 67.0% (0.025) — was 61.4%/62.6%/65.7%. Same
  monotone ordering, ~3-4pp higher across the board, 0.05 still the intermediate choice.
- **Conclusion: `l_step=0.05` remains the right choice; no re-decision needed.**

**Unexpected, and the most important number in this re-check: PSM (physics-only argmin
classification) top-1 accuracy jumped dramatically.** At each step's own discretisation σ:
0.555→**0.865** (step 0.1), 0.556→**0.904** (step 0.05), 0.562→**0.942** (step 0.025). The
R-grid fix wasn't only an S1.5 (load-axis) fix — the same R-L compensation that was corrupting
L-recovery was *also* corrupting the operator's ability to attribute observations to the correct
fault location. This is new information beyond what the S1.5 fix targeted, and it should be
reported alongside the S1.5/S1.6 results, not just filed under "R-grid housekeeping."

Full numbers: `results/pcstgnn/operator/lgrid_post_rgrid_fix/lgrid_summary.json`. Old numbers
preserved untouched at `results/pcstgnn/operator/lgrid/lgrid_summary.json`.

## S1.7 discretization sub-test (2026-09-25, `scripts/check_s1_7_discretization.py`)

The last open Gate-1 criterion. Implemented per spec: built a halved R grid (every second point
of the canonical 18-pt `grids.R_GRID` starting at index 0 → 9 points; this happens to retain all
three corpus values {0.1,1,10} exactly, so the test isolates pure grid-density loss from the
alignment fix) in a side directory only — **the canonical `operator/` table and its calibrated
`sigma_eps=7.2555e-4` were left frozen**, per the author's explicit instruction not to re-touch
already-passed work. Full 26-way PSM argmin (`residual.raw_residual`/`rho`, generalized past
`flatten_table`'s hardcoded NUM_R the same way `diagnose_rgrid_candidates.py` was) on the full
28,875-event training split, both tables scored at the identical frozen `sigma_eps`:

| R grid | n | macro-F1 (25-class localization) | top-1 acc |
|---|---|---|---|
| full (canonical, frozen) | 18 | 0.8977 | 0.8974 |
| halved | 9 | 0.8989 | 0.8987 |

**ΔF1 = −0.0013 (halved is marginally *better*, within noise) — PASS** against the <0.01
criterion, decisively. `results/pcstgnn/audit/s1_7_discretization/s1_7_discretization.json`.
