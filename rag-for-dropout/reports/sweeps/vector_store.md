Limits of this test (stated, not hidden): the corpus has only a few hundred vectors, so Chroma's HNSW (ef_search 100 or 200, above the corpus size) is close to exact search and cannot show an approximation loss. Re-run this benchmark when the corpus grows. Qdrant local mode always searches exactly; its approximate HNSW mode needs a Qdrant server, which was not run. Native hybrid search was not tested (the BM25 half of the hybrid retriever lives in this pipeline, outside the store).

**Rule (best + cheap, author 2026-11-02):** eligible = a real vector store (not the FAISS reference), native metadata filter works, dense top-10 identical to exact search, and the retrieved lists and all metrics identical to the reference end to end → chroma_default, chroma, qdrant_local. Quality is equal for all eligible stores, so the cheapest wins: lowest p95 latency; within 10 % of it is a tie and the order (qdrant_local, chroma, chroma_default) breaks it → qdrant_local. **Winner: `qdrant_local`.** The pipeline supports every store above with one setting (`vector_store.backend`); all eligible stores give the same ranking here, so switching to another one does not change a retrieval result.
